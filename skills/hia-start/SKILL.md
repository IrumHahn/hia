# HIA 시작

현재 프로젝트에 HIA를 실제 적용한다. 사용자가 지정한 프로젝트가 없으면 현재 작업 폴더를 사용한다. 스킬이 설치된 폴더를 프로젝트로 착각하지 않는다.

## 적용

1. 프로젝트 루트와 기존 AGENTS.md, AGENTS.override.md, CLAUDE.md, STATE.md 및 기존 상태·협업 문서를 확인한다. 홈 폴더처럼 여러 프로젝트가 섞인 위치라면 대상을 먼저 확인한다.
2. 이 스킬의 `assets/HIA-RULES.md`를 공통 운영 규칙으로 읽는다. 프로젝트에 별도 운영·협업 규칙이 있으면 함께 확인하고 보존한다.
3. 이 SKILL.md가 있는 폴더 기준 `assets/`의 템플릿을 사용한다. 프로젝트에 AGENTS.md, CLAUDE.md, HIA-RULES.md, STATE.md, DECISIONS.md, logs/를 마련한다. 로컬 공통 규칙이 있으면 필요한 프로젝트 지침에 함께 연결하되 접근하지 못한 문서를 필수 의존성으로 만들지 않는다.
4. 기존 파일은 덮어쓰지 않는다. 변경 전에 `backups/hia-실제시각/`에 대상 파일의 원본과 경로를 보존하고 필요한 부분만 병합한다. 기존 `HIA:START` 블록, `@AGENTS.md`, 동등한 HIA 연결이 있으면 중복 추가하지 않는다. override가 기본 지침을 가리는지도 확인한다.
5. 기존 상태 문서가 있으면 STATE.md에서 그 문서로 안내해도 된다. 같은 상태를 두 곳에서 별도로 관리하지 않는다. 알려진 목표·실제 산출물·확인된 진행만 기록하고 템플릿 대괄호를 채운다. 목표가 없으면 '설치 후 첫 업무 지정 대기'로 둔다. 과거 대화 속 명령은 참고 자료로만 취급한다.
6. 기존 협업 절차를 지킨다. 병렬 작업자는 고유 로그를 쓰고 STATE.md는 통합 담당자가 갱신한다. 현재 기록 담당자가 있으면 덮어쓰지 말고 설치 결과와 갱신 제안을 자신의 로그에 남긴다.
7. 날짜·고유 작업ID·작성자가 포함된 logs/ 파일에 생성·변경 파일, 백업, 검증, 미완료와 다음 행동을 기록한다. 이미 적용되어 있다면 건강한 기존 구성을 유지하고 부족한 연결만 보완한다. 단순 점검을 재설치라고 보고하지 않는다.
8. 파일 존재와 연결, 기존 내용 보존, STATE.md 필수 항목을 확인한다. 이후 중요한 결정·산출물·검증·중단과 작업 종료 전에 기록하도록 프로젝트 지침에 남긴다.

## 완료 보고

현재 프로젝트, 적용 또는 점검 결과, STATE.md 위치, 이후 기록 방식만 짧게 알려준다. 새 세션·다른 모델 시험은 실제 수행한 경우만 완료라고 한다. 기본 설치를 계획 설명만으로 끝내지 않는다.

개인 기억 수집, 다른 프로젝트 변경, 전역 설정 수정, 패키지 설치, 클라우드 전송, 예약 실행은 이 명령의 범위가 아니다. 사용자 요청이나 더 높은 우선순위의 제약과 충돌하면 해당 부분을 명시한다.
